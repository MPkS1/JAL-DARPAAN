PROBLEM STATEMENT: 26192 — Flash Flood Prediction System for Hilly Regions using Multi-Source Data
THEME: Disaster Management | CATEGORY: Software
IDEA: JAL-DARPAAN — AI Guardian Against Hill Flash Floods

1. THE PROBLEM
India's hill states face recurrent flash flood catastrophes — Kedarnath 2013, Chamoli 2021, Sikkim GLOF 2023 — that struck villages with little or no warning. The gaps in today's systems:
- Warnings cover whole districts (~50-100 km); nobody tells a specific village
- Lead time is a vague 12-24 hour regional forecast; flash floods need 1-3 hour nowcasting
- Only rainfall is used — soil saturation and slope, the key flash-flood drivers, are ignored
- Ground stations exist but data is siloed across portals; no one fuses them
- Alerts are black-box and carry no action information
India has ~40 million hectares of flood-prone land (NDMA). No operational village-level flash flood warning system exists in the country today. PS 26192 asks for exactly this gap to be closed.

2. PROPOSED SOLUTION — DETAILED
JAL-DARPAAN is a complete software platform. India's Hydrological Information System (HIS) already contains thousands of ground stations — our first step is to research and integrate them, not rebuild them.
- Built on India's existing station network (HIS): IMD operates ~1,000+ Automatic Weather Stations (AWS) and ~1,400 Automatic Rain Gauges (ARG); CWC runs river gauge/telemetry stations issuing forecasts at ~338 flood-forecast sites; hourly river-level telemetry is published openly via India-WRIS/NWIC
- Fuses 6+ free data sources: IMD station + gridded rainfall, satellite rainfall (GPM IMERG), NASA SMAP soil moisture, 30m terrain/slope (Copernicus DEM), Sentinel-1 radar, GSI landslide records, plus live CWC/WRIS river levels
- Low-cost ESP32 sensor nodes (₹1,500/node) deployed only at villages where the station audit shows a genuine coverage gap — every node's data flows into the same platform
- AI predicts the next 1-6 hours: LSTM/GRU nowcasts rain and soil saturation; LightGBM classifies village-level flood risk
- Village/ward-level risk map: every village colored green/yellow/orange/red, refreshed every 15-30 minutes
- Actionable alerts, not just warnings: SMS/Telegram/push with village name, flood arrival time, nearest safe shelter, evacuation route, and NDRF helpline (Hindi + local language)
- Explainable AI: every alert shows WHY it fired ("Soil 92% saturated + 45 mm/hr rain → HIGH risk") so officials trust it
- Runs on a 100% free/open-source stack: ₹0 software cost, replicable by any state

3. HOW IT ADDRESSES THE PROBLEM
- District-scale warnings → 30m terrain maps split the area into micro-watersheds giving village-level risk
- Vague 12-24 hr forecast → 1-3 hr hyper-local lead time with village name + arrival time
- Rainfall-only inputs → 6-source fusion + 2-source confirmation rule cuts false alarms
- Siloed station data → one fused platform: adapters for every source with automatic fallback to open feeds, so no single portal outage breaks the system
- Black-box alerts → SHAP explanations + shelter, route, helpline inside every alert

4. INNOVATION AND UNIQUENESS
- First village-level flash flood system for Indian hill micro-watersheds — existing global systems (GloFAS ~11 km grid, Google Flood Hub, FFGS) stop at district/major-river level
- Sensor strategy — augment, don't duplicate: we audit India's existing HIS stations and integrate them instead of building wasteful parallel networks; new hardware only for verified gaps
- Novel model ensemble for ungauged streams — LSTM + GRU + LightGBM, using free satellite proxies where no river gauges exist (most hill streams have none)
- Multi-source confirmation rule — HIGH/CRITICAL alerts fire only when ≥2 independent sources agree; first-line defense against alarm fatigue
- Trust through explainability — SHAP-powered "why this alert" in plain language
- Zero-cost replicability — ₹0/month infrastructure means any hill state, district, or NGO can adopt without procurement friction

5. TECHNOLOGIES TO BE USED (all free/open source)
- Frontend: React 18 + TypeScript + Vite · Tailwind CSS v4 · MapLibre GL (2D Esri imagery + 3D terrain, no API keys) · Recharts
- Backend: Python 3.12 + FastAPI — REST APIs, risk engine, alert service, JWT auth + RBAC. ✅ Already implemented in the project repository (backend/)
- Database: PostgreSQL + PostGIS, Redis — spatial data storage, real-time cache
- Authentication: JWT + role-based access — secure official/village access (National → State → District → Field → Village Pradhan)
- AI/ML: PyTorch (LSTM/GRU + ConvLSTM) · LightGBM · SHAP · TimesFM/Chronos zero-shot nowcasting
- Ground-station data (HIS): IMD AWS/ARG, CWC telemetry, India-WRIS/NWIC open feeds — free/open where published
- Satellite & terrain: GPM IMERG, NASA SMAP, Sentinel-1, Copernicus DEM — always open, always free (NASA/ESA)
- IoT (gap coverage only): ESP32 + MQTT (Mosquitto) + tipping-bucket rain gauge + soil probe — ~₹1,500-2,800/node, only at uncovered villages
- Hosting: Cloudflare Pages (frontend) + Render free tier (backend) + Neon PostgreSQL — ₹0/month, always-free

6. SENSOR RESEARCH — WHAT ALREADY EXISTS, AND IS IT PUBLIC?
Research finding: India's HIS sensing layer already exists — the gap is integration and village-level intelligence, not hardware.
- IMD AWS + ARG (~1,000 + ~1,400 stations): hardware exists; public access partial (real-time portal restricted Oct 2025) → our approach: district-level data via IMD request/MoU; fallback to IMD gridded rainfall + Open-Meteo
- CWC river gauges & flood-forecast stations (~338 sites): hardware exists; public access yes — hourly telemetry on India-WRIS/NWIC + AFF portal → direct API/dataset ingestion
- India-WRIS / NWIC (national water data): exists; open datasets → primary river-level feed
- Satellite rainfall/soil (GPM IMERG, SMAP, Sentinel-1): exists; fully open (NASA/ESA) → primary fusion inputs
- Terrain/DEM (30m) + GSI landslide records: mapped; open (Copernicus DEM, Bhukosh) → risk mapping + training labels
- ESP32 nodes (our addition): we build them → deployed only where the audit shows a genuine gap
The three real gaps this platform closes: (1) data access, not hardware — IMD locked its AWS/ARG real-time portal (Oct 2025); (2) hilly regions under-covered — stations sit in valleys and big towns; small hill villages and ungauged mountain streams have no nearby station; (3) no village-level fusion — nobody combines the existing sensors into village-level flash flood alerts.

7. METHODOLOGY — IMPLEMENTATION STEPS
- Step 1 — Research & Foundation: audit all IMD/CWC/State stations in the pilot district; repo + CI pipeline; village maps loaded into PostGIS; free data feeds verified
- Step 2 — Data Core: ingestion adapters for every source (open feeds first); 11-feature village vectors built; high-fidelity sensor simulator mirrors the exact ESP32 payload so real nodes plug in later without code change
- Step 3 — AI & Alerts: train LightGBM risk model (target AUC > 0.80); LSTM rainfall + GRU soil models; village risk map + Telegram/FCM/SMS alerts live for 200+ villages; 2-source confirmation rule
- Step 4 — Test & Harden: backtest against Kedarnath 2013 / Chamoli 2021 / Sikkim 2023 events; load, security, and backup-restore drills
- Step 5 — Pilot & Scale: pilot with one district disaster authority; deploy ESP32 nodes at audited gap villages; monthly model retraining; expand state-wide

System flow: Data Sources (existing IMD/CWC/WRIS stations + satellites + ESP32 nodes) → Ingestion Workers + source adapters → PostgreSQL + Redis → AI Engine (LSTM → GRU → LightGBM → Fusion) → Alert Dispatcher (Telegram/FCM/SMS) → React Dashboard — refreshed every 15 minutes.

8. SENSOR SIMULATION STRATEGY — SIMULATE NOW, PLUG IN REAL SENSORS LATER
Core principle: the AI model cares about the data FORMAT, not the source. Simulated and real sensor data use the identical format — so real nodes replace the simulator with ZERO code change.
- Now (build + demo): real station + satellite data + simulated ESP32 data
- Later (real sensors): real station + satellite data + real ESP32 data → zero code change
Simulated data is realistic, not random: (1) replays historical rainfall patterns — real IMD/satellite records scaled to a village; (2) adds monsoon-style random variation; (3) simulates failure cases too — node offline, battery low — to test the health-monitoring system.
Exact telemetry format both simulator and real ESP32 use (MQTT JSON):
{"node_id": "ESP32-UK-014", "village_code": "VN-2211", "timestamp": "2026-05-17T14:35:00+05:30", "rainfall_mm_hr": 45.2, "soil_moisture_pct": 88.4, "water_level_m": 1.42, "battery_pct": 92, "signal_dbm": -67}

10. POTENTIAL CHALLENGES, RISKS, AND MITIGATION
- Risk 1 — False alarms erode trust ("alarm fatigue") [High/High] → multi-source confirmation rule (≥2 sources must agree) + calibrated probabilities + SHAP transparency + alert cooldowns
- Risk 2 — Rare flood events → scarce training labels [High/High] → boost class weights + SMOTE; enrich labels from NASA global landslide catalog; anomaly-detection fallback model
- Risk 3 — IoT sensors fail in monsoon field conditions [High/Medium] → sealed solar enclosures; node health monitoring with offline alerts; platform continues on station + satellite data if any node drops
- Risk 4 — Ground-station data access varies (IMD portal restrictions) [Medium/Medium] → swappable source adapters — open India-WRIS telemetry + satellite rainfall + Open-Meteo fully cover operations; IMD station data pursued via district request/MoU
- Risk 5 — Free hosting limits as usage grows [Medium/Medium] → stateless containers migrate in one command; documented low-cost VPS upgrade path if ever needed

Primary users: village heads & ward officers · district disaster managers (DDMA/SDMA) · NDRF/SDRF teams · ~10,000+ residents of pilot villages. Economic benefits: ₹0 software licensing — public money stays public; avoided flood losses (India loses thousands of ₹ crore annually to floods); reuses India's existing station network instead of duplicating it — ₹1,500 ESP32 nodes only at verified gaps.

Environmental benefits: early landslide detection protects watersheds; solar-powered low-energy nodes with minimal footprint; open data supports long-term climate adaptation research.

13. KEY RESEARCH INSIGHTS
- India's HIS sensing layer already exists: IMD operates 1,000+ AWS and ~1,400 ARG; CWC issues forecasts at ~338 stations with hourly telemetry published openly on India-WRIS/NWIC — the missing link is integration and village-level intelligence, not new hardware (IMD/MoES, CWC/PIB)
- ConvLSTM improved flash-flood prediction accuracy by ~18% over standard LSTM — NASA study, Frontiers in Water (2024)
- Multi-source fusion (rainfall + soil + slope) reduces false alarms by 30%+ — flood-forecasting literature
- LightGBM/CatBoost offer the best speed+accuracy balance for flood risk classification — Scientific Reports (2025)
- Uttarakhand deep-learning + SHAP study found slope, rainfall, soil type, distance-to-stream as top predictors — Earth Science Informatics (2025)
- Mountain-specific models dramatically outperform grid-based models in hilly terrain — arXiv (2025)
- Existing operational systems are too coarse: GloFAS ~11 km grid; FFGS = district-level — Copernicus/WMO
- Where station gaps exist, a full IoT node costs only ₹1,500-2,800 (ESP32 + rain gauge + soil probe)

14. MARKET VALIDATION
